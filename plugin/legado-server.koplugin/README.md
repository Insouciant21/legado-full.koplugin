# Legado server for KOReader

独立的 V1 服务器客户端。WebUI 管理书源和书架并上架，服务器缓存完整章节后生成整本 EPUB；此插件配对后主动同步已上架内容，断网时直接阅读本地整本 EPUB，正文排版交给 KOReader。

将整个 `legado-server.koplugin` 目录安装到 KOReader 的 `plugins/` 下，并将旧的 `legado.koplugin` 移出该目录后完整重启。菜单入口为 **Legado server**；Kindle 上只保留这一套 Legado 入口。第一阶段不导入旧插件书架，也不修改旧插件的数据。

插件通过 KOReader 原生 gettext 加载自己的 `l10n/<locale>/legado-server.mo`。目前提供简体中文 `zh_CN` 翻译；未提供翻译的语言继续使用源码中的英文。

首层菜单只保留五个入口：

- **我的书架**：点按任一书籍直接续读到当前章节位置；长按书籍打开目录。书籍行会显示作者、`当前章节/总章节` 和全书百分比。
- **推送书籍**：查看已领取的 EPUB；首行用于主动检查服务器的新推送。
- **立即同步**：同步已上架书架、上传本地进度并拉取服务端进度。
- **同步中心**：查看同步状态、待上传进度和冲突，手动发送进度，并开关自动同步与自动接收推送。
- **服务器**：已配对时只显示连接信息和移除配对；未配对时才显示局域网发现和手动配对。

1. 在 WebUI 的 Kindle 设备页创建设备配对码。
2. 在 Kindle 的 **Legado server → 服务器** 中选择局域网服务器或手动输入地址，再输入配对码。
3. 在 WebUI 的导出弹窗选择“导出完成后自动推送到 Kindle”。
4. KOReader 在启动、恢复前台、联网或周期检查时会自动领取 EPUB；也可以在 **推送书籍 → 检查新推送** 中主动领取。
5. 在 **推送书籍** 中选择已领取 EPUB，或从 **我的书架** 打开服务器自动生成的整本 EPUB。

EPUB 推送独立于原有的已发布书架协议。服务器先把导出的全部文件复制到持久投递目录，Kindle 端逐个使用 `Range`/`If-Range` 续传，验证文件大小和 SHA-256 后原子改名；全部文件成功后才会向服务器确认。确认响应丢失时，同一游标和幂等设备身份会安全重试。推送书籍保存在 `legado-server/pushed/`，不会因服务端书架删除或导出缓存过期而消失。

自动领取只会在 KOReader 已联网时运行，不会主动唤醒 Kindle 的 Wi-Fi。WebUI 撤销设备后，服务器会拒绝旧设备令牌并取消尚未领取的投递；已经下载到 `legado-server/pushed/` 的 EPUB 会保留。

局域网连接优先使用 UDP 发现，默认端口为 `47832`。Kindle 会同时发送广播、多播和对本机已连接私有 IPv4 子网的单播探测；部分 Wi‑Fi 接入点会过滤设备间广播/多播，单播扫描保证这种网络仍能自动发现。单播扫描最多覆盖 510 个私网地址，超出 `/23` 的较大子网会收敛到本机所在 `/24`。服务器只响应私网、回环和链路本地来源，不响应公网来源；配对后 Kindle 保存稳定的 `server_id`，电脑 IP 因 DHCP 变化时会重新发现同一服务器并更新地址。若局域网策略同时阻止所有 UDP 探测，可以使用 **Pair manually** 输入一次 HTTP(S) 地址。

已上架书架以整本 EPUB 为主通道。插件先下载到书籍目录下的 `.part` 文件，校验大小和 SHA-256 后原子替换 `book.epub`，再应用书架快照；中断下载使用单段 `Range`/`If-Range` 续传，服务器返回全量 200 时丢弃旧前缀并重新下载。EPUB 内每章使用稳定章节 ID 作为文件名；KOReader 只打开一次文档，跨章翻页直接复用同一次排版会话，目录使用 KOReader 原生 TOC。旧服务器返回逐章 ZIP 时仍保留兼容安装逻辑，但整本 EPUB 书不会再下载逐章 bundle。

整本 EPUB 快照只为每章同步稳定 ID、序号、标题和完整性状态，不再重复发送内容哈希与路径。插件在安装时完成一次核对，并把结果持久化到 `epub-verifications.json`；后续 reset、重启和打开书籍复用该验证结果，避免在 Kindle 上反复散列数百 MB 内容。服务器重启后的首轮网络检查可以早于系统连接事件，因此自动任务在未联网时会按 30 秒重试，失败只写入日志，不弹中央或角标通知，也不会主动打开 Wi‑Fi。

针对 KPW4 的有限内存，首层菜单摘要只解析一次书架快照；同步请求开始时只保留游标，不会让两份完整书架对象同时存活。读取整本 EPUB 时，进度映射只计算当前章和下一章的起始页，不再在每次进度采样时遍历全书目录。

数据保存在 KOReader 数据目录的 `legado-server/` 中。整本 EPUB 使用稳定书籍 ID 路径，同一次同步内的 EPUB、章节列表和 SHA-256 绑定为一个不可变版本。**服务器 → 忘记服务器配对** 只移除设备令牌和服务器地址，已下载书籍及阅读状态继续保留，因此可安全地换服务器或重新配对。

阅读进度使用递增的十进制字符串 `device_seq` 和持久 outbox。翻页/滚动后最多 10 秒保存一次，关闭文档、休眠和手动同步前立即保存。上传按事件顺序执行：首次 wire payload 在网络请求前持久化，响应丢失后按同一 `event_id` 与同一 payload 重试；自家已确认版本只推进同一原始观察 anchor 上的后续事件，外来观察 base 交给服务端精确 CAS 判定。冲突及拒绝候选连同服务端结果持久保留。KOReader xpointer 只保留在本地；插件把 EPUB 的 `DocFragment` 映射回稳定章节 ID，再跨设备发送章节 ID 和章内比例。同一 EPUB 版本优先用本地 xpointer 精确恢复，EPUB 版本变化时按章节 ID 和章内比例恢复。书架点按也复用同一恢复路径，因此不会先进入目录或从章节开头重新阅读。

自动同步默认开启。KOReader 启动、恢复前台或 Wi-Fi 联网后会先上传本地进度，再拉取已发布书架的新章节和 canonical 进度；阅读期间最多每 5 分钟执行一次，任务使用不可见 trap，不弹同步窗口。关闭文档和休眠前会立即写入本地 outbox 并尽力安排上传，但插件不会主动唤醒 Kindle Wi-Fi。**同步中心 → 同步状态** 显示最后同步时间、待上传数和未解决冲突数，**阅读进度冲突** 可在服务端位置与本机位置之间二选一。WebUI 的 **Kindle 同步中心 → 阅读同步** 提供同一冲突列表和解决操作。

运行依赖为 KOReader 的 LuaJIT、rapidjson、LuaSocket/LuaSec、lfs、`ffi/archiver` 与 libarchive，以及 HTTPS 可信 CA 包；无需旧插件的 QuickJS 或书源规则。设备 token 只用于同一配对服务器，HTTP 重定向不会自动跟随。初期 HTTP 可用于可信局域网，公网应使用 HTTPS。

构建安装包会同时编译翻译目录：

```bash
make plugin-server-zip
```
